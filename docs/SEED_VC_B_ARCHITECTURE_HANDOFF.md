# B 方案架构与接替 AI 交接：Seed-VC 歌声转换

更新日期：2026-10-26

## 1. 已确认的决策

用户的目标是：优先中文的高质量 AI 翻唱，覆盖素材清洗、个人音色训练、歌声转换、混音和导出，最终整理为可发布到 GitHub 的项目。

用户选择了前一轮推荐方案：**先以 A（RVC/Applio 专人训练）为主线，架构预留 B（Seed-VC）**，并明确要求写出 B 的架构文件交给接替 AI。本文件是 B 的实施设计，不代表 B 已经实现。

本次交接前仅进行了目录查看和 GPU 查询，未安装依赖、下载权重、运行训练、推理或整曲验收。`E:\rvc` 在写本文档前为空。检测到 NVIDIA GeForce RTX 5080，显存 16303 MiB。GPU 可见不等于 PyTorch/CUDA、第三方算子已兼容。

## 2. 模型选择及已知约束

- 上游：https://github.com/Plachtaa/seed-vc
- 选择 **V1 的 44.1k、F0 条件歌声模型**，而不是按版本号直接选择 V2。
- 歌声配置：`configs/presets/config_dit_mel_seed_uvit_whisper_base_f0_44k.yml`。
- 对应预训练权重：`DiT_seed_v2_uvit_whisper_base_f0_44k_bigvgan_pruned_ft_ema.pth`。文件名中的 `v2` 不代表要使用上游 V2 语音转换架构。
- 训练是在上述预训练权重上微调个人音色，不是从零训练通用基础模型。
- 微调后推理仍需要参考音频；音色包必须保存参考音频的本地关联。
- 原仓库已归档，应固定具体 commit，自行验证 RTX 5080 和依赖兼容性，不跟随浮动 main。
- 上游代码采用 GPL-3.0；发布前核对固定版本中的许可证以及各辅助权重的条款，保留出处和所需声明。不要假设整个组合项目都能直接按 MIT 发布。

上述信息来自本轮方案调研，实施前应对固定 commit 的源码和配置再次确认。不要把本文件中的示意接口当成上游现有 API。

## 3. 产品与技术边界

一个中文本地 Web 工作台同时服务 A、B。B 作为可选引擎，不接管共享的音频分离、数据集管理、任务管理和混音模块。

建议以 Python 后端、SQLite 本地任务数据库、磁盘产物目录实现首版。前端通过任务 API 读状态和产物；长任务交给独立 worker 进程。A、B、分离组件采用独立环境和进程，避免 PyTorch、NumPy、音频库等版本冲突。前端具体技术可以随 A 的实现确定，不应为了接入 B 重建 UI。

首版优先 Windows + NVIDIA。本机直接运行是主验收环境，Linux 支持需单独验证后才能宣称可用。

## 4. 共享流程

### 4.1 训练素材

```text
用户导入素材
  → 解码与音频信息检查
  → 按需分离人声
  → 按需提取主唱、去混响、轻度降噪
  → 切片与异常筛查
  → 人工试听、剔除坏片
  → 固定数据集版本，划分训练/验证素材
  → B 微调
  → 检查点试听和选择
  → 导出音色包
```

建议首先收集 10–30 分钟干净的中文歌声，覆盖高低音、气声、长音和辅音；这是项目建议，不是最低运行条件。上游要求每条训练音频为 1–30 秒，应在提交训练前自动校验。

避免相邻切片分别进入训练与验证集；按原始录音或歌曲分组划分，降低验证泄漏。清洗后音频和原始音频均保留，处理强度可撤回。素材质量优先于总时长。

### 4.2 翻唱

```text
歌曲或已有干声
  → 人声/伴奏分离（已有干声时跳过）
  → 可选主唱提取、去混响
  → 选择 B 音色包或零样本参考音频
  → F0 条件歌声转换
  → 分段拼接、时间与音量检查
  → 可选 EQ、压缩、混响
  → 与伴奏混合
  → 导出干声、伴奏、混音和参数清单
```

优先通过 audio-separator 接入 BS-RoFormer / MelBand RoFormer。具体分离和去混响权重另建注册表，通过中文试听选定，不在这里锁定未经实测的“最佳”权重。

去和声不是默认强制步骤。允许保留原和声、单独转换和声或整体转换，并在 UI 标明所选行为。主唱分离失败时必须允许人工替换干声。

## 5. 引擎适配契约（拟实现）

所有请求通过 JSON 文件或结构化消息交给独立 worker；不依赖解析控制台文本来判断成功。命令通过参数列表启动，禁止拼接用户输入到 shell 命令。

```python
class SingingEngine:
    def capabilities(self) -> dict: ...
    def validate_environment(self) -> dict: ...
    def validate_dataset(self, dataset_manifest: str) -> dict: ...
    def train(self, request: dict, events) -> dict: ...
    def convert(self, request: dict, events) -> dict: ...
    def export_voice(self, voice_id: str, destination: str) -> dict: ...
```

B 的 capability 应明确：支持零样本、支持微调、需要参考音频、支持移调；是否支持精确断点续训以实际 worker 验证结果为准。

`train` 请求至少包含：数据集版本、基础权重 ID、配置 ID、随机种子、批大小、最大步数、保存间隔、恢复检查点。微调参数按显存实测生成预设，不预先承诺固定批大小。

`convert` 请求至少包含：源干声产物 ID、音色包 ID 或参考音频 ID、引擎版本、移调半音数、扩散步数、CFG、分段策略、随机种子。对“保留原旋律”的默认预设关闭自动音高对齐；如开放自动音高调整，需显示其对旋律的影响。

上游 CLI 参数以固定版本源码为准。适配器显式映射产品字段，不将产品字段名直接透传。

返回值至少包含：产物清单、实际使用参数、运行环境摘要、警告、耗时和错误详情。输出缺失、无法解码、包含非有限采样或明显截断时不能报告成功。

## 6. 数据与产物模型

建议目录：

```text
apps/web/                       # 共用中文 UI
src/core/                       # 任务、数据集、产物、配置
src/audio/                      # 分离、清洗、切片、拼接、混音
src/engines/rvc/                # A 的适配器
src/engines/seed_vc/            # B 的适配器和 worker
configs/engines/seed_vc/        # 产品预设及上游映射
scripts/                       # 安装、诊断、下载、启动
vendor/                        # 固定上游源码；具体纳入方式待定
models/                        # 共享预训练权重，默认忽略
data/datasets/<id>/<version>/   # 素材、切片、manifest，默认忽略
data/voices/<voice_id>/         # 检查点、参考音频和清单，默认忽略
outputs/jobs/<job_id>/          # 每一步产物与日志，默认忽略
docs/                          # 架构、安装、训练、翻唱说明
```

关键 manifest：

- 数据集：原始文件哈希、来源文件 ID、切片区间、处理链、采样率、有效时长、划分和人工排除记录。
- 音色包：引擎、上游 commit、基础模型 ID/哈希、配置、选定检查点、参考音频、数据集版本、兼容版本及来源说明。
- 产物：类型、路径、哈希、父产物、实际参数和创建任务。至少区分分离人声、处理后干声、伴奏、转换干声和最终混音。

音色包导出使用相对路径，换机器导入后重建引用；不导出本机绝对路径或训练原始素材。检查点、参考音频属于本地数据，默认不提交 Git。

## 7. 长任务、显存与恢复

任务状态：`queued → running → succeeded / failed / cancelled`；恢复生成新的运行记录并关联旧任务。步骤完成后先写临时产物，通过校验后原子提交。

- 单卡默认只执行一个 GPU 密集阶段；分离、训练、转换共享显存调度锁。
- CPU 解码等阶段可以并行，但必须限制数量和内存。
- 在 B 微调前卸载分离模型；独立进程退出后释放显存。
- 推理按句或受控长度分段，保留偏移与上下文；上下文裁剪后再交叉淡化，防止重复歌词和整曲漂移。
- 显存不足时记录失败配置，允许用户或明确的降级策略缩小分段/批大小；不得静默改变模型或跳过片段。
- 训练取消先尝试正常保存，超过宽限时间再停止进程。区分“恢复训练状态”和“仅加载权重重新训练”。
- 缓存键覆盖输入哈希、模型哈希、参数和处理版本；更换模型后不得误用旧结果。

## 8. 安装与 Git 发布

首阶段先验证 RTX 5080 对当前 PyTorch/CUDA wheel 和所需算子的支持，再固定 Python、PyTorch、CUDA runtime 与音频依赖。不要直接复用多年以前的整合包依赖锁。

安装器应提供环境诊断和分组件安装。模型清单记录来源 URL、文件名、哈希、版本、许可证和用途；下载支持重试及校验。镜像地址可配置，不默认修改系统全局环境。

仓库包含源码、依赖锁、模型清单、中文文档、示例配置、第三方声明和必要验证。忽略虚拟环境、权重、数据集、音色包、缓存、输出、数据库、密钥和机器私有配置。

Git 发布验收包含：在干净目录按 README 安装启动，能明确提示缺失模型，下载后可跑最小流程。普通 CI 验证配置、任务与音频处理契约；GPU 训练和整曲验收另存实测记录，不伪造 CI 已验证 GPU。

## 9. 接替 AI 的实施顺序

1. 先检查已有 A 代码与仓库指令；沿用共享任务、UI 和产物模型。本文件不是让你立即替换 A。
2. 固定 Seed-VC commit 和模型清单，检查依赖与许可证，完成本机 GPU 自检。
3. 先用一段短干声和参考音频跑通官方歌声推理，记录真实耗时、显存和输出质量。
4. 封装 B worker 与引擎适配器，接入共享任务系统，实现取消、失败和产物验证。
5. 跑通最小微调、检查点保存和重新加载；随后验证恢复语义及参考音频绑定。
6. 接入整曲分离、分段转换和混音，检查拼接、时长、响度和导出。
7. 用相同数据与歌曲比较 A、B，完善中文预设和安装文档，整理可发 Git 的源码。

## 10. 验收标准与待验证项

必须真实完成一次“导入素材 → 清洗 → 微调 → 加载自训模型 → 整曲翻唱 → 导出”。零样本演示不能代替训练验收。

至少选择普通中文流行、气声/长音、高音密集三类片段进行 A/B 试听，统一输入、移调和混音响度，记录咬字、目标音色相似度、原唱残留、齿音、破音、长音和接缝。试听与自动指标结合，不以单个指标宣布绝对最佳。

记录每阶段耗时、峰值显存、有效素材时长、训练步数和确切版本。检查所有中间文件可播放，最终时长与原曲一致且无明显漂移；对时长偏差设可配置阈值，超限后禁止静默通过。

目前尚未验证：RTX 5080 依赖组合、最大可用批大小、训练耗时、整曲速度、最佳分离权重、微调收益及两引擎实际音质差异。接替 AI 应先测量，再把结果写入实施记录。
